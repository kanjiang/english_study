# 小词星（EnglishApp）第一期设计

日期：2026-08-25  
状态：待用户确认后进入实现计划

## 目标

做一个面向 3–8 岁、第一期界面和词库按 5–8 岁设计的英语记忆 App（Android + iOS）。第一期可玩闭环是：

**主题记忆游戏 → 赚金币 → 给固定卡通形象换装 → 家长云端控制每日使用时长。**

对标小小优趣的「好玩 + 家长管时长」，不做动画片，不做完整宠物家园。

工作名：**小词星**。Flutter 包名：`english_app`。界面文案用简体中文，游戏内容用英语。

## 非目标（第一期不做）

- 分级动画播放、跟读、点读
- 完整宠物家园（房间、摆放家具）
- 一个账号多个孩子
- 自建服务器、微信登录
- 家长网页后台（家长也在同一个 App 里操作）
- 防破解客户端（改金币、改已用时长）的硬防；只做正常孩子路径和基础 Firestore 规则

## 技术选型

- 客户端：Flutter（一套代码出 Android / iOS）
- 状态：Riverpod
- 云端：Firebase Authentication（邮箱密码 + 手机号验证码）+ Cloud Firestore
- 音频：`just_audio`，单词读音打进安装包，不依赖在线 TTS
- 最低系统：Android 8.0（API 26）、iOS 13
- 时区：所有「今天」按 `Asia/Shanghai` 的日历日计算

## 架构

三层，禁止界面直接读写 Firestore。

1. **界面（features）**：登录、孩子首页、三款游戏、换装店、时长锁、家长区
2. **规则（domain）**：出题判分、金币与库存、每日额度与锁屏判定、离线合并
3. **数据（data）**：Firebase 仓库 + 本地缓存。整份 `users/{uid}` 快照和当前 `usedSeconds` 写入 `shared_preferences`，杀进程后能恢复计时和锁屏状态

三款游戏共用 `QuizEngine`（出题、选项、对错、连对）。主题只是外壳：

| 主题 | 题型 | 答对反馈 | 答错反馈 |
| --- | --- | --- | --- |
| 寻宝翻牌 | 图+词翻牌配对 | 翻开配对成功、得宝石 | 翻回背面 |
| 消防员灭火 | 听音选图 | 喷水灭掉一团火 | 火不灭，换下一题 |
| 打怪兽 | 看图选词 | 打出一击，怪兽掉血 | 攻击落空 |

不引入 Flame 或物理引擎。动画用 Flutter 自带 Widget / 简单 `AnimationController`。

## 账号与角色

- 一个 Firebase 用户 = 一个家长 + **恰好一个**孩子档案
- 打开 App：未登录 → 登录/注册；已登录 → **孩子首页**（不是家长区）
- 首次登录必须：给孩子起名、从 **4 个系统头像** 里选一个、设置 **6 位家长数字密码**（只用于进家长区，不是 Firebase 密码）。密码存储为 `SHA-256(uid + pin)`，不明文保存
- 家长区入口在首页角落，需输入 6 位密码；输错 5 次后锁定 1 分钟
- 忘记家长密码：用邮箱或手机号重新验证 Firebase 登录后重置

孩子设备与家长设备用同一账号。家长在自己手机改每日限额后，孩子设备通过 Firestore 快照在数秒内更新。

## 孩子首页

固定展示：当前穿戴的卡通形象、金币数、今天剩余分钟数。

三个大入口：寻宝翻牌、消防员灭火、打怪兽。点形象进入换装店。

剩余秒数 = `(dailyLimitMinutes + bonusMinutes) * 60 - usedSeconds`，最小为 0。剩余 0 秒时三个游戏和换装店都不可进，直接进入时长锁。首页显示见「时长控制」。

## 游戏规则

- 词库第一期 **48 个词**，4 类各 12 个：动物、食物、颜色、家居。每个词含：英文、中文释义、图片资源、英语读音音频
- 听音选图、看图选词每局 **10 题**；寻宝翻牌为 **6 对（12 张）**，全部配完即结束
- 每一题只判一次：听音/看图答对 +3 金币，当前连对 ≥ 3 时额外 +1；答错不扣金币、连对清零，**立刻进入下一题**，不能靠反复重试刷分
- 寻宝翻牌：两张不配对则翻回（牌仍留在场上，这是记忆玩法本身），连对清零；只有配成一对才算答对并给金币
- 消防员答错：本团火不灭，换下一题（下一词）；打怪兽答错：攻击落空，换下一题
- 一局结束回首页，立刻看到金币变化
- 计时在游戏进行中继续；剩余时间为 0 时：允许把 **当前正在答的一题** 答完（含当前音频播完），然后不再出新题，进入时长锁。本局已得到的金币保留

## 换装店

- 一个固定卡通形象（不可换角色）
- 9 件商品：帽子 ×3、眼镜 ×3、上衣 ×3，价格 20 / 40 / 60 金币各一档
- 金币足够且未拥有才能买；购买成功后立即拥有，可穿上或脱下
- 不能重复购买同一件；不能穿未拥有的
- 离线不能购买（见「离线」）

## 时长控制

只统计 **本 App 在前台** 的时间。切到后台或锁屏时暂停计时；回到前台继续。强制杀掉 App 前会把 `usedSeconds` 写入本地并尽量同步云端。

字段：

- `dailyLimitMinutes`：家长设置，可选 20 / 30 / 45 / 60，默认 30
- `bonusMinutes`：家长临时加时，每次 +10，可多次。新的日历日开始时清零
- `usedSeconds`：今日已用秒数。限额换算为秒（例如 30 分钟 = 1800 秒），`usedSeconds >= 限额秒数 + bonus 秒数` 时锁屏
- 首页「还剩 N 分钟」：`N = ceil(剩余秒数 / 60)`；剩余 0 秒显示「时间到了」
- `usedOnDate`：`YYYY-MM-DD`（上海时区）。日期变化时：`usedSeconds = 0`，`bonusMinutes = 0`

有网时用 Firestore 服务器时间判断是否换日。完全没网时用设备本地上海时区日期（已知限制：可改系统日期骗出「新的一天」）。

**时长锁：** 全屏，不能进游戏和商店。文案：「今天的学习时间用完了，请爸爸妈妈来帮忙。」孩子本机解锁只能通过家长区验证后加时。第二天额度自动恢复则锁消失。

家长区可做：查看今日已用、改每日限额、临时 +10 分钟、修改登录邮箱/手机、重置家长数字密码。

限额被改小且今日已用已超新限额：孩子端在当前题结束后立刻锁。

同步：有网时每 30 秒、以及每次离开游戏/切后台时上报 `usedSeconds`。家长改限额走实时监听，立刻生效。

## 数据模型

Firestore 文档：`users/{uid}`

```text
email: string | null
phone: string | null
parentPinHash: string          // 6 位密码的单向哈希，不明文存储
child: {
  name: string
  avatarId: string             // 系统头像 id
  coins: int
  ownedItemIds: string[]
  equipped: { hat: string | null, glasses: string | null, clothes: string | null }
}
time: {
  dailyLimitMinutes: int       // 20 | 30 | 45 | 60
  bonusMinutes: int
  usedSeconds: int
  usedOnDate: string           // YYYY-MM-DD Asia/Shanghai
}
gameStats: {
  treasureLastScore: int
  firefighterLastScore: int
  monsterLastScore: int
}
```

安全规则：仅 `request.auth.uid == uid` 可读写该文档。第一期购买用客户端事务扣金币、加库存；不引入 Cloud Functions。

本地缓存完整镜像。冲突规则：

| 数据 | 权威 | 说明 |
| --- | --- | --- |
| 计时与是否锁屏 | 本地，联网后与云端合并 | 取 **较大的 usedSeconds**（同一 `usedOnDate`），防止关网逃避；换日后按新日期重置 |
| 金币 | 云端 + 尚未上报的 **本局合法得分** | 禁止用「本地总金币」覆盖云端 |
| 装扮购买 | 仅在线、云端事务 | 离线只允许穿已拥有的 |

## 离线与失败

- 曾经登录成功：可离线玩已内置的三款游戏；计时和锁屏仍生效
- 未登录过：必须联网登录
- 登录/验证码失败：留在登录页，中文错误提示
- 时长上报失败：本地继续计时，不因此增加额度
- 购买失败：金币与库存不变，提示「现在买不了，稍后再试」
- 监听限额失败：沿用本地已有限额，恢复网络后再听

## 测试

**规则单测：** 判分与连对；购买与穿戴；额度用尽要锁、+10 分钟解锁、换日清零；金币合并（云端 100 + 未上报合法 20 = 120）。

**界面测：** 未登录→登录页；已登录→孩子首页；时长用尽全屏锁且游戏/商店不可进；家长验证加时后锁消失；三款游戏可打完一局并回首页且金币变化。

**手工真机：** 家长手机改限额，孩子设备数秒内跟上；飞行模式玩到锁，恢复网络后另一设备看到同一额度；购买失败金币不变；Android 与 iOS 各走一遍登录、一局游戏、换装、锁屏。

第一期不做自动截图巡检和压测。上架前另补隐私政策与后台耗电检查，不在本次实现计划内。

## 模块边界

| 模块 | 做什么 | 怎么用 | 依赖 |
| --- | --- | --- | --- |
| `QuizEngine` | 出题、判分、连对、本局金币 | 三款主题传入词库与题型 | 词库资源 |
| `TimeQuota` | 累计前台秒数、是否该锁、换日、加时 | App 前台生命周期调用 | 本地时钟 + 可选服务器时间 |
| `Wallet` | 加金币、购买、穿戴 | 游戏结束与商店调用 | 云端事务（在线购买时） |
| `AuthSession` | 登录态、孩子档案、家长 PIN 校验 | 启动与家长区 | Firebase Auth |
| 主题外壳 | 只负责画面和音效，把选择回传引擎 | 各游戏页 | `QuizEngine` |

## 成功标准

第一期完成的标志：家长能用邮箱或手机号注册并设好一个孩子；孩子能打完三款主题游戏并得到金币、买一件装扮穿上；家长能设每日时长并在另一台设备上看到孩子被锁或被加时。
